# Open Notes

[Сайт](https://opennotes.github.io/) · [Редактор](https://opennotes.github.io/edit.html)

Редактор Markdown для локальных файлов и папок. Установленное приложение запускает редактор напрямую.

## Разработка

Рекомендуется Node.js 24 LTS и npm. Поддерживаются также Node.js 22.13+ и 26+.

```sh
npm ci
npm run dev
```

Vite выводит адрес локального сервера. Главная страница — `/`, редактор — `/edit.html`.
Все зависимости включаются в сборку через npm; CDN не используется. Service worker отсутствует.

## Структура проекта

Единственный источник приложения — `src/`. Страницы в `dist/` создаёт Vite:
их не редактируют вручную. Готовая сборка коммитится вместе с исходниками для публикации. Корневых HTML-страниц и отдельного корневого `public/` нет.

```text
src/                           Исходники приложения
  index.html                   Главная страница
  edit.html                    Редактор
  css/                         Стили страниц
  js/
    entries/                   JS-точки входа HTML
    controllers/               Контроллеры Stimulus
    files/                     Модель, чтение, кэш, запись и .gitignore
    editor/                    Markdown и сохранение документа
    search/                    Поиск без DOM
    ui/                        SVG-иконки
    bootstrap.js               Запуск редактора
    home.js                    Запуск установленного приложения
    install.js                 Установка webapp
  public/                      Статика, копируемая без преобразования
    assets/                    Иконки и изображения
    manifest.webmanifest       Настройки webapp
tests/                        Проверки приложения
  unit/                        Модульные тесты
  e2e/                         Браузерные тесты и производительность
  scenarios/                   Сценарии, используемые браузерными тестами
  support/                     Тестовое окружение и файловые модели
  fixtures/                    Файлы для тестов
  policies/                    Проверки правил линтеров
scripts/                       Инструменты разработки
.github/workflows/             Проверки и публикация
```

В корне остаются README, `package.json`, lock-файл и конфигурации инструментов.
Новые страницы, код, стили и ресурсы добавляются в `src/`, тесты — в `tests/`.
`src/public/` содержит только файлы с постоянными URL; JS и CSS подключаются из
`src/js/` и `src/css/` и обрабатываются Vite. Файлы из `src/public/` копируются
в `dist/`, поэтому совпадающие изображения в сборке — ожидаемый результат.

Генерируемые каталоги: `dist/`, `coverage/`, `test-results/`, `playwright-report/`.
`node_modules/` содержит установленные зависимости. Зависимости, кэши и отчёты исключены из Git; `dist/` хранится в репозитории как готовая сборка.
`npm run clean` удаляет сборку, отчёты и временные кэши, сохраняя исходники и зависимости.
После очистки `npm run build` создаёт `dist/` заново. Перед коммитом сборку нужно восстановить. Для локальной разработки используется
`npm run dev`, для просмотра сборки — `npm run preview`.

## Архитектура редактора

`workspace` координирует открытие проекта и переключение файлов. `tree` управляет деревом,
клавиатурной навигацией, перетаскиванием и диалогами операций. `editor` управляет CodeMirror,
toolbar и предпросмотром. `search` управляет поисковым окном и горячими клавишами.
Каждый контроллер владеет своими DOM-targets и снимает обработчики при отключении.
Связи между контроллерами объявлены через Stimulus Outlets. CSS-классы состояний
объявлены через `static classes` и настроены атрибутами `data-*-class` в `src/edit.html`;
обычные классы разметки остаются в HTML и построителях элементов.

Один экземпляр `Project` хранит файлы и текущее состояние проекта; один `ProjectReader`
обслуживает чтение и общий кэш. Модули файловых операций, поиска и сохранения документа
не обращаются к DOM или Stimulus. Выбор строки дерева передаётся событием `tree:select`;
координатор сохраняет текущий документ перед переключением. Открытие результата поиска
ожидает завершения переключения перед выделением найденного текста.

Правила корневого и вложенных `.gitignore` применяются при загрузке папки, до обхода исключённых
директорий. Исключённые пути не попадают в дерево, поиск и фоновый кэш. Данные `.git` также
пропускаются. После сохранения `.gitignore`, его переименования, перемещения или удаления
папка с доступом к диску пересканируется автоматически. Новый список применяется целиком;
ошибка или устаревшее пересканирование сохраняют прежний список. В загруженных через input
папках новые исключения применяются сразу; для возврата ранее исключённых файлов папку нужно
выбрать заново. Поиск учитывает текущий текст открытого `.gitignore`.

Компоненты управляют своим состоянием через методы (`reset`, `setBusy`, `selectPath`,
`revealMatch`), а координатор задаёт порядок операций. Поиск не зависит от CodeMirror.
Открытие документа и поиск совместно используют выполняющееся чтение текста; старый запрос
не может заменить кэш более нового содержимого.

## Проверки

```sh
npx playwright install chromium firefox webkit
npm run check
```

`check` выполняет проверку форматирования, ESLint, Stylelint, тесты с покрытием, браузерные
сценарии и проверку production-сборки в Chromium, Firefox и WebKit. В браузерных сценариях используются настоящий CodeMirror,
Stimulus и OPFS, а в модульных тестах — контролируемые файловые модели для проверки ошибок и гонок.

| Команда                      | Назначение                                                  |
| ---------------------------- | ----------------------------------------------------------- |
| `npm run test`               | Модульные тесты                                             |
| `npm run test:watch`         | Тесты при редактировании                                    |
| `npm run clean`              | Удаление сборки, отчётов и временных кэшей                  |
| `npm run coverage`           | Покрытие всех файлов `src/js/**/*.js`                       |
| `npm run test:e2e`           | Браузерные сценарии и проверка скорости                     |
| `npm run test:performance`   | Только проверка переключения файлов                         |
| `npm run test:dist`          | Сборка и проверка опубликованного приложения                |
| `npm run test:compatibility` | Готовая сборка в Firefox и WebKit                           |
| `npm run test:policies`      | Проверки собственных ESLint-правил и архитектурных запретов |
| `npm run lint:fix`           | Автоматическое исправление JavaScript и CSS                 |
| `npm run lint`               | JavaScript и CSS, без предупреждений                        |
| `npm run format`             | Форматирование исходников                                   |
| `npm run audit:runtime`      | Аудит зависимостей приложения                               |
| `npm run audit`              | Аудит всех npm-зависимостей, включая инструменты разработки |

Порог покрытия — **100% строк, функций, ветвей и выражений**. Исходные файлы приложения не
исключаются из отчёта; сторонние зависимости, тесты и конфигурация сборки не входят в эту метрику.
HTML-отчёт: `coverage/index.html`, отчёт для CI: `coverage/lcov.info`.

Набор инструментов и команда `check` основаны на
[Orchid Charts](https://github.com/orchidsoftware/charts/tree/85e552c7183a7973659591cb65a0a5349549c8a4),
с адаптацией для приложения вместо библиотеки. Конфигурации сверены с этой версией 10 октября 2026 года.

ESLint включает Import X, Promise, Security, SonarJS, Unicorn, Node и JSDoc, а для модульных
тестов — Vitest. Проверяются циклические импорты, ранние возвраты, порядок импортов, сложность
функций (до 12), глубина блоков (до 3), размер функций (до 35 строк), параметры (до 3),
когнитивная сложность (до 15) и описание контрактов. Собственные правила проверяют многострочные
массивы, возвращаемые объекты и размер отдельных тестов (до 60 строк). Файловая модель и поиск
не могут импортировать контроллеры и представления редактора.

Stylelint задаёт стандартные правила и порядок CSS-свойств Recess. Prettier сохраняет ширину
110 символов и размещает элементы массивов исходного кода на отдельных строках. `.gitattributes`
фиксирует LF и отделяет изображения от текстовых файлов.

Адаптации указаны в конфигурациях: имена Stimulus-файлов сохраняются; свойства общих моделей
и DOM изменяются с сохранением их идентичности; гонки проверяются тестами владения запросами.
Последовательные записи и зависимые обходы имеют локальные исключения `no-await-in-loop` с
объяснением. Подмены асинхронного браузерного API в тестах не обязаны содержать `await`.
`Promise.withResolvers` не требуется из-за поддержки Safari 17; Safari-префиксы и классы
CodeMirror разрешены в CSS. Правила, относящиеся только к API Charts, не перенесены.

CI также проверяет инструменты на Node.js 22.13 и 26, запускает аудит зависимостей приложения,
CodeQL и проверку изменений зависимостей. Публикация npm-пакета, SSR и проверки его деклараций
типов относятся к библиотеке Charts; Open Notes проверяет обе страницы готовой Vite-сборки.

Полный `npm run audit` отдельно сообщает о девяти high-записях в инструментах Stylelint:
они связаны с одним [неисправленным advisory для `braces`](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
Зависимости приложения не затронуты. Проверка изменений зависимостей в PR остаётся строгой
и может блокировать добавление затронутых инструментов до исправления upstream.

## Сборка и публикация

```sh
npm run build
npm run preview
```

На статический HTTPS-хостинг размещается **содержимое `dist/`**. В сборке есть обе HTML-страницы,
локальные зависимости, CSS, manifest и иконки. Относительный `base` позволяет размещать приложение
как в корне домена, так и в подпапке.

GitHub Actions запускает проверки при push и pull request. После успешных проверок ветки `main`
публикуется `dist/` через GitHub Pages. В настройках репозитория **Pages → Build and deployment →
Source** необходимо выбрать **GitHub Actions** вместо публикации исходников из ветки.

## Установка приложения

Откройте редактор по HTTPS. В Chrome на Mac воспользуйтесь установкой приложения в адресной строке,
в Safari на macOS Sonoma 14+ — «Файл → Добавить в Dock». Для автосохранения Chrome или Edge должен
получить разрешение на изменение выбранной папки. При отсутствии файлового API изменения скачиваются.

Manifest задаёт `start_url: ./edit.html?app=1`. Последняя папка доступна через «Продолжить»;
браузер может снова запросить разрешение. Элемент `<install>` используется при поддержке браузером,
с резервной кнопкой и инструкцией установки.
